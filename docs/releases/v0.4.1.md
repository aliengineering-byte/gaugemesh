# GaugeMesh 0.4.1 — numerical evidence integrity patch

This developer-preview patch fixes a finite-number JSON round-trip defect found
by a real external consumer of the 0.4.0 public binary. That binary accepted all
four steps but returned `GM_RUN_INTEGRITY` on export. A source regression
reproduced the failure during storage reload. The existing serde_json dependency
now uses its `float_roundtrip` parser; no new library, database schema, execution
engine or domain-specific gateway branch is introduced.

Existing 0.4.0 tags and artifacts are unchanged. Use 0.4.1 for the numerical
consumer. Retain failed evidence; upgrading does not promise to repair an
already inconsistent snapshot, and must never replay an uncertain side effect.
The 0.4.0 neutral Tasks/Run results remain their recorded results, not evidence
that the newly exposed numerical case passed.

## Optional external consumer

The release source includes
[an educational section-mechanics review](../../examples/concrete_review/README.md).
It uses the same public Tasks/Run interface and needs Python, not Rust. It asks
for explicit units, loads, material assumptions and consent; runs four immutable
stages; compares a bounded primary solution with an independent Decimal active-set
calculation; and produces self-contained HTML/Markdown plus offline-verifiable
structured evidence. All formulas remain in optional example files, outside the
binary and default dependencies. The example is qualified on Linux x64.

Only the original declared prescribed-strain section response is evaluated.
The optional caller-defined rule is labelled SYNTHETIC. ACI/ASCE entries are
official public metadata, not licensed rules, adoption or errata implementation.
Authorized rule requests return SOURCE_AUTHORIZATION_REQUIRED. Nonconvergence
can be an honestly completed Run while numerical verification remains
NOT_EVALUATED. No design capacity, safety, compliance or construction approval is
provided; real decisions require qualified professional/authority review.

## Gates and unchanged boundaries

The required source gates exercise the numerical storage regression, mechanics
fixtures, independent units, steel states, refusals, nonconvergence, report
tampering, and a real gateway stop/resume with one accepted input execution.
The release gate downloads fresh public archives, checks checksums/attestations
and source identity, and reruns both neutral consumers and this optional consumer.
Raw acceptance evidence is retained in `public-install-verification`.

The [bounded Run contract](../durable-runs.md) is unchanged: local Unix surface,
16 steps, concurrency up to four, exactly one attempt, explicit driver activity,
no watchdog, and reconciliation rather than replay after uncertain effects.
Remote and Windows Runs are not qualified. Cancellation acknowledgement is not
worker termination. Integrity hashes are not signatures.

The historical ResiliReplay result remains **3 PASS / 10 FAIL / 13, PARTIAL**;
post-response trace mutations are not live-wire recovery proof.
GitHub Releases and public GHCR remain the distribution channels. Both crates
keep `publish = false`; there is no crates.io work.
