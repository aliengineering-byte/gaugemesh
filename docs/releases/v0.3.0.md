# GaugeMesh 0.3.0 — Durable MCP Tasks developer preview

GaugeMesh `0.3.0` adds bounded, durable routing for the MCP 2026-07-28 Tasks
surface. The existing GaugeMesh product identity and 2025-11-25 behavior remain
intact; the older revision does not advertise Tasks.

## What ships

- SQLite-backed task records with caller-scoped idempotency, persisted dispatch
  ownership, public GaugeMesh task IDs, write-once upstream task binding, and a
  bounded terminal-result cache;
- exact upstream-session fencing, capability-manifest pins, conservative
  reconciliation, explicit effect authority, and fail-closed discovery bounds;
- standard `tasks/get` and `tasks/cancel` routing for known public IDs, while
  `tasks/update` is deliberately rejected because update intent and receipt are
  not persisted by this bounded contract; and
- a domain-neutral qualification path in every native release archive.

Run the qualification directly from the released binary:

```sh
gaugemesh verify --durable-tasks
```

The command uses real child processes and MCP stdio, reopens the SQLite task
router while retaining the same live upstream session, and checks stable public
identity, one observed fixture effect, changed-input conflict, invalid or
missing artifacts, unsupported updates, and poll-driven deadline cancellation.
The fixture is qualification support, not a production executor.

## Recovery evidence

`gaugemesh verify --resilireplay` invokes the exact public
`resilireplay@0.7.0` CLI. The corrected thirteen-row matrix remains honestly
`PARTIAL`: 3 rows pass—the genuine clean control plus the trace-level synthetic
timeout and deterministic-error retry rows—and 10 rows fail. All twelve fault
runs observe their requested trace mutation, complete cleanup, and report zero
duplicate effects.

ResiliReplay applies those mutations to its recorded trace after a real MCP
response; it does not inject them into the MCP wire or GaugeMesh server. The two
retry passes therefore do not prove recovery from a real wire-level timeout or
server/tool error, and the ten failures are neither waived nor represented as
target rejections. No MCP-RES profile or certification claim is made.

## Guarantee boundary

GaugeMesh does not claim exactly-once external effects, transparent recovery
across a gateway or provider reconnect, a background scheduler, a worker
watchdog, or independent verification of arbitrary provider output. Persisting
before dispatch and refusing automatic ambiguous resubmission constrain what
GaugeMesh itself does; they cannot establish what an upstream completed before
a response was lost. Deadline cancellation begins only when a caller later
polls, and a cancellation acknowledgement does not prove that an external
effect was prevented or reversed.

## Distribution

GitHub Release archives and the public multi-architecture GHCR image remain the
supported distribution paths. The release workflow verifies checksums,
provenance attestations, packaged-binary execution, public-image execution, and
digest-pinned Official MCP Registry metadata. Both Rust crates remain
`publish = false`; crates.io is not a distribution channel for this release.
